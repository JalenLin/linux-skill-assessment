## 壓力測試結果（60 人）

測試環境：Intel N305（8 核 E-core）、48GB RAM、NVMe、PVE 9、local-lvm。
60 個帳號、12 題（9 題 LXC、3 題 VM），模擬整場測驗。

| 情境 | 結果 |
|---|---|
| 預先建立 720 個實例 | 0 失敗，約 8 秒一個（PVE 的 LVM 操作是一個一個來），720 個約 1.5 小時 |
| 60 人同時開 LXC 題 | 0 失敗；開好時間中位數 64 秒、最久 115 秒 |
| 120 個環境同時運作（90 LXC＋30 VM） | 記憶體 20.5GB |
| 60 人同時開 VM 題 | 0 失敗；CPU 滿載約 3.5 分鐘；中位數 111 秒、最久 192 秒 |
| 51 LXC＋70 VM 同時運作 | 平時 35~37GB；同時檢查時最高 43.8GB（91%），用到 0.9GB swap |
| 60 人同時按檢查，同時量終端機反應 | 全部完成；終端機回應最慢 0.3 秒（不受影響） |
| 最終校驗 165 個實例 | 13 分鐘（同時 8 個檢查） |

**每個環境的實際記憶體**：LXC 約 50MB，VM 約 450MB（設定 1GB，實際用不到）。

**結論與設定：**

- 「每位作答者同時運作的環境數上限」設 **1**（預設）：60 人最多 60 個 VM ≈ 27GB，48GB 主機有餘裕。
  設 2 時最壞情況 120 個 VM ≈ 54GB，會超過 48GB
- 瓶頸是 **CPU（大量 VM 同時開機）** 與 **PVE 一次只能做一個 clone**，不是網站本身
- 網站（lsa-web，4 核 4GB）在 60 人下 CPU、記憶體都很輕鬆

## 容量規劃

**記憶體** ≈ 4GB（PVE＋lsa-web）＋ 同時運作的環境數 × 每個環境記憶體

| 人數 | 每人同時 1 題、全是 LXC | 每人同時 1 題、全是 VM |
|---|---|---|
| 30 | 6GB | 18GB |
| 60 | 7GB | 31GB |
| 100 | 9GB | 49GB |

**CPU**：作答與檢查時很輕；大量 VM 同時開機會塞車（N305 上 60 台約 3 分鐘）。
實際測驗作答者不會在同一分鐘點同一題，會比測試輕。測驗前提醒作答者「VM 題第一次開要等 1~2 分鐘」。

**時間**：

| 動作 | 時間 |
|---|---|
| 建置一題範本＋自我測試 | LXC 1~2 分鐘；VM 3~5 分鐘 |
| 預先建立實例 | 約 8 秒一個（N 人 × M 題 × 8 秒），**測驗前一天做** |
| 刪除實例 | 約每分鐘 25 個磁碟 |
| 最終校驗 | 約 5 秒一個（同時 8 個；fstab 類會重開機的題目較久） |

## 儲存空間（LVM）上限

PVE 預設的 `local-lvm` 用 LVM-thin，每個實例是一個 LVM 磁碟（VM 題含 cloud-init 盤共 2 個）。
**LVM 的 metadata 區只有約 1MB，是安裝 PVE 時就固定的，事後不能放大**；
實測大約 **1500 個磁碟**（約 1100 個實例）就會滿，之後建立環境會失敗：

```
VG pve metadata on /dev/... exceeds maximum metadata size
```

硬碟空間本身通常還很多（linked clone 很省空間），是「數量」先到上限。

**對策：**

1. **只為已綁定編號的帳號預先建立**（預設）
2. 「系統設定」的**全系統實例總數上限**（預設 1000），預先建立前會檢查
3. 「題組」列表顯示目前總實例數；**題組結束、成績確定後刪除該題組的實例**（成績保留）
4. 查看目前用量：
   ```bash
   vgs -o vg_name,lv_count,vg_mda_size,vg_mda_free pve
   ```
5. 需要更多：加一顆硬碟，用較大的 metadata 建立新的 VG／thin pool
   （`pvcreate --metadatasize 64m`），在 PVE 加為儲存空間，設定檔 `pve_storage` 指向它，
   重新建置所有範本；或改用 ZFS（沒有這個數量限制）

60 人 × 12 題的測驗約 720 個實例、950 個磁碟，在上限內；但要記得清掉練習題組的實例。

**LVM 設定備份的累積**：每次建立／刪除磁碟，LVM 都會在 `/etc/lvm/archive` 留一份設定備份，預設保留 30 天。
壓力測試（建立＋刪除約 1500 個磁碟）後累積了 1 萬多個檔案、3.3GB。系統碟空間不多時可以清掉舊的：

```bash
du -sh /etc/lvm/archive
cd /etc/lvm/archive && ls -t | tail -n +101 | xargs -r rm -f     # 只留最新 100 份
```

或在 `/etc/lvm/lvm.conf` 的 `backup { }` 區塊把 `retain_days` 調小（例如 7）。

## 常用指令

在 PVE 主機上：

```bash
pct exec 100 -- journalctl -u lsa -f            # 網站紀錄
pct exec 100 -- systemctl restart lsa           # 重啟網站（測驗中避免）
pct exec 100 -- sqlite3 /var/lib/lsa/data/lsa.db   # 直接查資料庫
pvesh get /pools/lsa                                  # lsa pool 裡的所有 VM/CT
vgs pve; lvs pve | wc -l                               # LVM 用量
free -m; uptime                                        # 記憶體、負載
```

## 疑難排解

**作答者說終端機連不上**

- 題目頁按「重新連線」；仍不行請作答者按「重置環境」（回到初始狀態，作答內容會消失）
- 作答者可能改壞了 SSH（sshd 設定、`user` 帳號、網路設定），重置即可
- 後台作答者頁看該題實例狀態；「實例」頁可手動停止／啟動

**檢查顯示「評分程式無法登入環境」**

- 作答者改壞了 root 的 SSH 或網路，或環境開不起來（例如改壞 fstab 導致無法開機）
- 系統已自動重試一次；作答者重置本題後重做

**建置範本失敗**

- 題庫 → 題目頁看建置紀錄，通常是 setup.yml 的 Ansible 錯誤
- 建置時需要上網：確認 PVE 主機能上網、`pve-setup.sh network` 的 NAT 規則有在
  （`iptables -t nat -L LSA-NAT`）

**開題很久或失敗**

- 很多人同時開 VM 題時 CPU 會滿載，等 1~3 分鐘
- 「建立環境失敗」：查網站紀錄；若出現 LVM metadata 的錯誤，見上方「儲存空間上限」
- PVE 介面的工作紀錄（Tasks）可看 clone／start 的錯誤

**主機記憶體不足**

- 確認「每位作答者同時運作的環境數上限」是 1
- 「實例」頁「全部停止」可立即釋放（內容保留）

**忘記後台密碼**

- PVE 主機 `/root/lsa/admin_password`；或改 `config.yaml` 後 `./pve-setup.sh config` 再重啟網站

## 已知限制

- 單台 PVE 主機；不支援叢集分散
- 使用預設 `local-lvm` 時，全系統大約 1100 個實例就會到 LVM metadata 上限，見[儲存空間（LVM）上限](#儲存空間lvm上限)
- 重新建置範本後，舊範本若仍有作答者實例在用會保留；之後刪了那些實例，舊範本不會自動刪除，
  需要時到 PVE 手動刪除（`tmpl-<題目id>`，VMID 9100 以上、不在後台題庫頁顯示的那個）
- 服務重啟時，進行中的檢查會中斷（作答者重按即可）；測驗中請不要更新程式
